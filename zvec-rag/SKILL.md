# zvec-rag：本地知识库检索与引用

这是执行清单。核心约束只有一条：**说得出的结论必须指得回原文；指不回去的，就说明指不回去。**

## 1. 何时用

用：

- 用户的问题可能由**已上传到知识库**的文档回答。
- 回答前需要核实事实、给出引用来源。
- 用户明确提到某个知识库名称（如「agent-book」「智能体书籍」）。

不用：

- 问的是当前代码库、文件内容、实时网络信息——这些该用 `read` / `grep` / `glob` / `web_search`。
- 知识库尚未上传文档或从未成功构建索引——没有可检索快照，检索必然空手而归。

**检索不能替代阅读。** 命中片段是证据的**入口**，不是证据本身。要下判断时，用 `read` 打开 `source_path` 读上下文。

## 2. 检索前：把 collection 定下来

`collection` 可省略。省略时：

- 只有一个已构建知识库 → 直接检索它。
- 多个 → 工具返回**知识库清单**（含 id、名称、构建状态）。从中选一个，再调一次。

清单里 `id` 形如 `kb_agentbook_5eed`。**不要凭记忆猜 collection id**，它是 `<domain>_<hex>` 形式，猜不中。

## 3. 查询构造

一次调用只问一件事。检索质量主要取决于查询措辞，而非 topk。

- **用文档里会出现的词，而不是你的抽象概括。** 语料是中文技术书，就问「多 Agent 协作 handoff」而不是「分布式智能体架构」。
- **专有名词优先全文匹配。** 但要注意：仅有全文精确匹配、无向量证据的命中会被算作 `fts_only_hits`，分数固定很低，**通常被阈值过滤掉**。所以裸查一个专有名词返回空，不代表文档里没有它——见 §6。
- **多个独立问题分开查**，不要塞进一个 query。4 个独立查询并行发出去，比 1 个复合查询准。
- 首轮没命中时，**换词重试**比调 topk 有效。

`topk` 上限 50，省略时按该知识库配置的检索策略。默认不要显式传 topk——配置里已有合适的值。

## 4. 解读返回：分数与 band

每次命中都带两个信号：

- `match_score`：0..1 归一化，越大越相关。**这是归一化后的分数，不是原始距离**，不能跨知识库比较。
- `band`：由 `match_score` 派生的四档——`strong` / `relevant` / `fair` / `low`。

解读纪律：

- **不要因为分数不是 0.9 就否定命中。** 混合检索（稠密 + 全文 RRF 融合）的分数分布整体偏低。**`fair` 档常常就是正确答案**——本项目实测「OpenAI 相关」这类语义宽泛的查询，命中普遍落在 `0.55–0.78`（`fair`～`relevant`）。
- **`band` 决定你的语气强度**，不是决定要不要用这条证据：
  - `strong` / `relevant` → 可以直接作为论断依据。
  - `fair` → 可以引用，但要克制措辞，不要升级成普适结论。
  - `low` → 只当作线索，不要单独支撑结论。
- **全部命中都是 `fair` 或更低时，必须在回答里说明证据强度有限。** 不要让读者以为这是高置信检索结果。

## 5. 引用回溯：每次检索后必须附来源

**这是硬性要求。** 只要检索了并使用了命中内容，回答下方就必须有引用区。

每条引用给到**可回溯**的程度——读者要能自己走过去看一眼：

```
来源：<source_path>:<line>  [band score]  字符 <char_start>-<char_end>
```

- 优先用工具返回的 `source_path`（工作区相对路径）与 `line`。这是**可点击**的定位。
- 若 `source_path` 缺失，退回到 `file` + `ordinal` + `char_start/char_end`，并**明确说明这是不可解析的标识**，不要伪装成可点击路径。
- 若 `file` 也退化成裸 `doc_id`（形如 `doc_0fe75264`）——那是**内容哈希，对人类无意义**。必须如实说明来源名无法解析，而不是把它当成文件名贴出来。

引用区形式：

```markdown
---
**引用来源**（kb_agentbook_5eed）
1. `.dsh-kb-zvec/kb_agentbook_5eed/sources/doc_ffb5b037.md:212` [relevant 0.78] — GPT-5.6 原生 Deep Research 能力
2. `.dsh-kb-zvec/kb_agentbook_5eed/sources/doc_64616be9.md:28` [fair 0.69] — 语音架构的三种范式
```

**禁止**：

- 把 `match_score` 丢掉只留文件名。
- 引用一个自己没实际读过的命中，当作已核实。
- 把 `char_start-char_end` 区间当作行号——**字符偏移不是行号**。

## 6. 空结果：不要说「知识库没有」

空结果返回 `ok=false` 与 `reason: 'empty_result'`，并附两个计数：

- `below_floor`：**被阈值过滤掉的命中数**。
- `fts_only_hits`：仅全文精确匹配、无向量证据的命中数。

正确表述分三种，**不要混为一谈**：

| 工具返回 | 意思 | 该怎么说 |
|---|---|---|
| 空 + `below_floor: 0` + `fts_only_hits: 0` | 确实没有相关内容 | 「知识库里没有找到相关依据」 |
| 空 + `below_floor: 100` | **有命中，全被阈值挡了** | 「有候选但都低于相关性阈值——可能是确实弱相关，也可能阈值偏高」 |
| 空 + `fts_only_hits: N` | 查询词**精确存在**，但缺向量证据 | 「查询词在文档中精确出现，但向量证据不足；降低阈值可能召回」 |

关键：`below_floor` 很大时，**这信息本身就是发现**，要报告出来，而不是压成一句「没找到」。

其他失败原因按 `reason` 区分：`timeout`（预算耗尽）/ `cancelled`（调用方撤回）——**这两者语义不同，不要都说成超时**；`collection_not_found` / `discovery_needed` 对应 §2。

## 7. 回答写法

1. **先给结论**，再给依据。不要把检索过程絮絮叨叨铺在前面。
2. **区分三件事**：文档明确说了什么 / 你从文档推断出什么 / 文档没说但你知道的。第三类要标注出来。
3. **带出原文措辞**。关键论断尽量引用命中片段里的原句（片段很长时截取相关句），中文语料就保留中文。
4. **不要在证据之外补齐细节**。知识库里没有的内容，宁可说没有，也不要从通识里补一段读起来很顺的话——那会让整篇回答的可信度一起下降。
5. **回答长度匹配问题**。一个窄问题配一篇长综述是失真。
6. **引用区放在回答下方**，见 §5。

- [ ] 引用带了 `source_path` / 行号，或如实说明了无法解析？

- [ ] 全 `fair` 时说明了证据强度？
- [ ] 空结果时转述了 `below_floor` / `fts_only_hits`，而不是「没找到」？
- [ ] 有没有把推断当成文档原话？
