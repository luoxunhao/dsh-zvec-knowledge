# DSH 知识库插件（基于 zvec）设计规范

## 1 文档说明

### 1.1 编写目的

本文档是「DSH 知识库插件」的设计规范（Design Spec），用于把设计阶段的视觉与交互决策，固化为可执行、可校验、可交接的工程约束。文档与设计稿同源：设计稿画布为唯一视觉真源，本文档为唯一文字规格真源，两者出现冲突时以设计稿为准并回写本文档。

### 1.2 适用范围

适用于本插件的界面实现、组件开发、设计走查与后续视觉迭代评审。覆盖知识库创建、文档上传、索引构建、知识检索工具与 RAG 问答五条功能链路所涉及的全部界面。

### 1.3 读者对象

前端开发工程师（按第 3、4、9 章落地）、插件与后端工程师（按第 9 章对齐 zvec 与 DSH 契约）、设计与产品评审人（按第 2、6、7、8 章验收）。
### 1.4 术语与约定

| 术语 | 含义 |
|------|------|
| 设计令牌（Token） | 承载颜色、间距、圆角、字号等原子视觉决策的命名变量，是设计与代码之间唯一的对接层 |
| 知识库（Collection） | 对应 zvec 的集合概念，是检索与索引的最小隔离单元 |
| 文档（Doc） | 上传到知识库的单个源文件，经切分后成为若干分片 |
| 分片（Chunk） | 文档切分后的最小检索命中单元，携带 token 数与来源定位 |
| 命中分数（Match Score） | 对 zvec 距离归一化后的相似度分数，取值 0 至 1 |
| 状态胶囊（Status Pill） | 承载就绪、构建中、失败、待构建四种生命周期状态的行内标记 |
| 语义色 | 表达状态含义的颜色，与品牌色严格分工，不互相替代 |

约定：本文档中出现的十六进制色值均为浅色主题取值，深色主题取值见 3.5 节；所有尺寸单位为像素（px）。

## 2 产品与设计目标

### 2.1 产品定位

本插件是面向 DeepSeek Harness 的本地知识库插件，基于 zvec 进程内向量数据库构建。插件的核心价值是把「文档」变成「可被 AI 检索的知识」，并在不引入独立服务的前提下完成闭环：文档留在本地，索引留在本地，检索与生成通过插件暴露的工具完成。

因此界面需要同时服务两类人：一是建立与维护知识库的工程使用者，二是通过会话调用知识检索工具、消费 RAG 结果的最终用户。前者需要参数级的控制力，后者需要结果级的可信度。

### 2.2 插件能力范围

设计覆盖以下五条功能链路，任何界面元素都应能追溯到其中至少一条。

| 序号 | 能力 | 界面载体 |
|------|------|----------|
| 1 | 创建知识库 | 总览页主按钮；索引策略配置页 |
| 2 | 上传文档 | 知识库详情页拖拽上传区与文档列表 |
| 3 | 构建知识库 | 索引构建流水线、进度与构建日志 |
| 4 | 知识检索工具 | 会话内嵌的工具调用折叠块；检索测试页 |
| 5 | RAG 问答 | 检索测试页右侧回答面板与引用回溯 |

### 2.3 设计目标与原则

**目标一：状态一眼可读。** 知识库和文档存在明确的生命周期，用户最常问的问题是「它现在能不能用」。因此颜色、胶囊、进度三者必须在同一屏内自解释，不允许用户点击后才明白状态。

**目标二：参数改动可见后果。** 切分与嵌入参数直接决定检索质量，且配错后代价很高（需重建索引）。因此所有策略配置面都必须先给出预览与代价预估，再提供提交入口。

**目标三：结果必须可回溯。** RAG 回答必须能指回具体文档与段落。用户对生成内容保持怀疑是常态，界面要主动提供验证路径，而不是要求用户相信。

基于以上目标，确立以下设计原则。

1. **颜色不兼职。** 品牌色只承担主操作、选中态与焦点态；语义色只承担状态表达。二者不得互相借用。
2. **深度靠边框，不靠投影。** 层级优先用描边与底色差表达，投影只保留三级并仅用于浮层，避免多层阴影堆叠造成的脏感。
3. **状态不靠颜色单独承载。** 每个状态标记必须同时具备文字、实色与描边，保证色觉障碍用户与灰度打印场景下依然可读。
4. **技术值一律等宽。** 集合标识、分片数、分数、时间戳统一使用等宽字体与等宽数字，保证列表纵向对齐。
5. **不暴露内部数值。** 原始向量距离属实现细节，对外只呈现归一化后的分数与分档，避免用户基于不可解释的数值做判断。

**关于 component 组的补充说明。** v1.1.0 的 Scale 集只覆盖间距、圆角、字号、控件高度与布局尺寸，组件级尺寸（标签高 26、胶囊 26/22、徽标 20、图标按钮 34×34、开关 38×22、进度条高 5、集合图标 38×38 等）未纳入。这会使「业务样式不得出现非令牌尺寸」在组件层无法达成——组件实现必然产生裸尺寸。v1.1.1 补齐该组，使该原则可执行，而不是被迫放宽验收。

**关于 layout 组新增三项的说明。** §6.5 要求索引策略配置页「为双栏结构」，§6.4 要求检索测试「左侧查询卡…右侧回答面板」左右联动，但 v1.1.0 的 layout 组没有双栏几何令牌，实现只能自行写死尺寸——实测后果是内容区被限在 880px，在 1440 及更宽的屏幕上只占约一半宽度。故补三项：`--kb-split-max-width`（双栏页面最大宽度 1600）、`--kb-split-columns`（栏数 2）、`--kb-split-column-min`（单栏可读最小宽度 420）；同时把 `--kb-panel-max-width` 由 880 调整为 1200。这三项与 §6.4/§6.5 的页面结构一一对应，使「双栏」是可断言的实现契约而非描述性文字。

| mono | 11 / 16 | JetBrains Mono Medium | 令牌、标识与技术数值 |

### 3.7 尺度令牌

间距以 4 像素为基础单位，实际界面中绝大多数场景只使用 8、12、16、24、32 五个档位。

| 类别 | 令牌 | 值 |
|------|------|-----|
| 间距 | space1 / space2 / space3 / space4 / space5 | 4 / 8 / 12 / 16 / 20 |
| 间距 | space6 / space8 / space10 / space12 / space16 | 24 / 32 / 40 / 48 / 64 |
| 圆角 | radiusXs / radiusSm / radiusMd | 4 / 6 / 8 |
| 圆角 | radiusLg / radiusXl / radiusFull | 12 / 16 / 999 |
| 字号 | sizeMicro / sizeCaption / sizeBodySm / sizeBody | 11 / 12 / 13 / 14 |
| 字号 | sizeTitle / sizeTitleLg / sizeH2 / sizeH1 | 16 / 20 / 24 / 32 |
| 控件高度 | controlSm / **controlMd** / controlLg | 28 / **34** / 40 |
| 布局尺寸 | sidebarWidth / topbarHeight | 240 / 56 |
| 组件尺寸 | component 组（30 项） | 见 3.1 说明与令牌源文件 |

**controlMd 取值修订（v1.1.1）。** v1.1.0 此处记 32，但 4.1 按钮 md 尺寸、4.2 文本框高度、4.3 下拉与分段控件高度均为 **34**。三处组件定义一致而此处单处为特例，故以组件定义为准，`controlMd` 修正为 34。若后续判定应以 32 为准，则需同步修改上述三处组件规格，不能只改一处——否则同一表单内控件高度不一致，违反下一条规则。

圆角使用规则：控件与标签使用 radiusXs 至 radiusSm，卡片与输入框使用 radiusMd，弹窗与抽屉使用 radiusLg，容器与上传区可使用 radiusXl，胶囊与头像使用 radiusFull。

控件高度使用规则：表格内操作使用 controlSm，页面与表单默认使用 controlMd，空状态与表单提交使用 controlLg。同一表单内控件高度必须一致。

**组件尺寸与全局尺度令牌的边界。** 结构性尺度（间距、圆角、字号、控件高度、布局尺寸）由 3.7 的 Scale 集承担；单个组件自身的固定尺寸（标签高、胶囊高、徽标高、图标按钮边长、开关尺寸、进度条高度、表格行高与各列表列宽等）归 `component` 组。判别标准是：**同一尺寸会被多个不相关组件复用时归 Scale，只服务特定组件形态时归 component。** 该边界使「业务样式不得出现非令牌尺寸」这一原则在组件层也可达成。

### 3.8 层级与阴影

层级系统只有三级，全部用于浮层，常规卡片不投影。

| 层级 | 用途 | 阴影参数 |
|------|------|----------|
| level-1 | 内嵌卡片、输入框、分段控件选中项 | 偏移 0 1，模糊 2，扩散 0，rgba(16,19,26,0.06) |
| level-2 | 悬浮卡片、下拉菜单 | 偏移 0 4，模糊 12，扩散 -2，rgba(16,19,26,0.08) |
| level-3 | 弹窗与抽屉 | 偏移 0 12，模糊 32，扩散 -8，rgba(16,19,26,0.12) |

### 3.9 令牌工程接入

令牌已在设计文件中注册为变量，支持导出为三种格式供前端接入。

| 导出格式 | 适用场景 |
|----------|----------|
| W3C Design Tokens JSON | 构建期消费，接入令牌转换工具链 |
| CSS 自定义属性 | 直接引入，双主题通过选择器切换 |
| SCSS 变量 | 与既有 Sass 工程集成 |

深色主题通过变量模式切换，实现上对应 CSS 自定义属性的主题选择器覆盖。禁止在业务样式中硬编码色值，所有颜色与尺寸必须引用令牌。

## 4 基础组件规范

### 4.1 按钮

全局每个视图只允许出现一个 primary 主按钮。危险操作必须配合二次确认，不允许点击即触发删除。

| 变体 | 填充 | 描边 | 文字色 | 用途 |
|------|------|------|--------|------|
| primary | #4F5BD5 | 无 | #FFFFFF | 页面唯一主操作 |
| secondary | #FFFFFF | #CBD2DE | #3A424E | 次级操作 |
| ghost | 无 | 无 | #4F5BD5 | 弱化操作、行内入口 |
| danger | #DC2E4C | 无 | #FFFFFF | 不可逆操作 |

尺寸规范如下。

| 尺寸 | 高度 | 左右内距 | 字号 | 用途 |
|------|------|----------|------|------|
| sm | 28 | 12 | 12 | 表格内操作 |
| md | 34 | 16 | 13 | 默认操作 |
| lg | 40 | 20 | 14 | 空状态与表单提交 |

状态规范：default 使用主色，hover 使用 #4149BF，pressed 使用 #343BA0，disabled 使用填充 #E0E3F8 配文字 #A6ACE9，loading 保持主色并前置旋转指示器、文字改为进行时描述。

### 4.2 表单控件（输入类）

| 控件 | 规格 | 关键约束 |
|------|------|----------|
| 文本框 | 高 34，圆角 6，描边 #CBD2DE，内距 12 | 标签置于控件上方，辅助说明置于下方 |
| 聚焦态 | 描边 2px #4F5BD5，外发光 4px 15% 主色 | 不使用投影表达聚焦 |
| 搜索框 | 同文本框，左侧内嵌放大镜图标，图标与文字间距 8 | 聚焦态描边同步变主色 |
| 文本域 | 最小高度 62，圆角 6，内距 12，行高 21 | 用于知识库说明等长文本 |

负向校验统一使用 danger 语义色描边并附错误说明；校验信息必须说明原因，不允许只提示「输入有误」。

### 4.3 表单控件（选择类）

| 控件 | 规格 | 关键约束 |
|------|------|----------|
| 下拉选择 | 高 34，右侧内嵌下箭头，箭头与文字间距 8 | 选中值超长时截断并保留完整值的悬浮提示 |
| 开关 | 38 × 22，圆角 999，滑块 16 | 开为主色，关为 #CBD2DE；开关行必须附文字说明 |
| 复选框 | 16 × 16，圆角 4 | 选中为主色填充配白色勾选 |
| 单选 | 16 × 16 圆形 | 选中为主色描边配主色实心点 |
| 分段控件 | 高 34，圆角 8，底 #EDEFF4，内距 3 | 选中项为白底配 level-1 阴影；选项数建议 2 至 4 个 |

### 4.4 标签与计数徽标

标签用于表达分类与属性，高度 26，圆角 6，字号 12。中性标签填充 #EDEFF4，品牌标签填充 #EEF0FB 配主色文字，可移除标签在文字右侧追加 12 像素关闭图标并将右内距压缩至 8。

计数徽标高度 20，圆角 999，字号 11 等宽字体。数值超过两位时显示「99+」，不允许无限增长撑破布局。

### 4.5 状态胶囊

状态胶囊是业务状态的标准载体，高度 26，圆角 999，内距 10，字号 12 Medium。必须同时满足三个条件：携带文字、具备实色或实色圆点、具备描边。仅靠颜色区分状态属于违规实现。

状态胶囊在列表、卡片、表格与详情页中保持同一规格，密度更高的表格单元格内可压缩高度至 22 并取消圆点，但文字与描边必须保留。

### 4.6 图标按钮、分段控件与选项卡

图标按钮尺寸 34 × 34，圆角 6，图标 16 × 16。必须提供悬浮提示与可访问名称，禁止无文字且无提示的纯图标操作。主色图标按钮用于高频关键操作，例如重建索引。

分段控件与选项卡的区别在于：分段控件用于同一视图内的切换（如文档 / 索引 / 日志），选项卡用于层级更深的区域切换。选项卡选中态使用主色文字配 2 像素主色下划线，未选态使用 #5B6472 文字。

### 4.7 组件状态清单

**本节的状态要求适用于「交互控件」层**（分层定义见 8.1）。标记、容器与指示器三层不适用五态要求：为状态胶囊、计数徽标这类不可操作的标记编造 hover 与 loading 态，会产生用户永不触达的状态并使状态语义失真；标记层改为受「状态三件套」约束（4.5）。

交互控件必须实现以下五态，缺一视为未完成。

| 状态 | 要求 |
|------|------|
| default | 静息外观。作为基准样式，不构成独立规则 |
| hover | 可感知的反馈，不使用位移以外的夸张动效 |
| focus | 必须可见，使用主色描边与外发光，禁止移除轮廓 |
| disabled | 降低对比度但保持可读，必须能被读屏识别为不可用 |
| loading | 保持尺寸稳定，禁止因加载导致布局跳动 |

**按页唯一主操作。** 同一页面同一时刻只允许一个 primary 按钮（详见 8.3）。该约束是静态的：不因空态与列表互斥、或按钮处于不同容器而放宽。

## 5 业务组件规范

业务组件由基础组件组合而成，覆盖插件的四个关键任务与两类策略配置。同一模块在列表页与会话内嵌视图中复用，仅改变密度，不改变信息结构。

### 5.1 知识库卡片

承载身份、状态与规模三类信息。

| 区域 | 内容 | 规格 |
|------|------|------|
| 卡头 | 集合图标 38 × 38 圆角 9，名称为 title 级，技术标识为 mono 级，格式形如 `kb_prod_2f8a · HNSW` | 状态胶囊固定右上角 |
| 规模行 | 文档数、分片数、近七日命中次数 | 使用 mono 字体与等宽数字 |
| 分隔线 | 1 像素 #EDEFF4 | 仅在卡片内使用 |
| 页脚 | 更新时间左对齐，操作右对齐 | 操作默认隐藏，选中或悬浮时出现 |

名称与技术标识必须同时存在：名称服务人，技术标识服务排查与日志对账。

### 5.2 文档接入

上传区必须可被键盘触达，并具备明确的焦点态。上传区文案分两行：主文案说明操作方式，次文案说明可接受的格式与体积上限。

单文件上传在列表行内展示进度，不弹出全局遮罩。文档行包含：类型图标 18 × 18、文件名、文件体积、进度条与百分比、取消入口。进度条高 5，圆角 3，槽色 #EDEFF4，填充主色。

### 5.3 索引构建流水线

构建过程固定分为四个阶段：解析文档、切分与嵌入、写入索引、校验与发布。

每个阶段必须同时给出节点状态与阶段名称，禁止只显示无文字的进度条。节点状态使用三种形态：完成为主色或语义实色配勾选，进行中为主色实心配白色内点，未开始为浅灰描边。进行中的阶段名称使用主色，未开始阶段使用三级文字。

阶段条下方为整体进度，必须给出「已处理数量 / 总量」与百分比。构建日志默认折叠，展开后使用等宽字体，按时间戳顺序排列，成功行使用青绿，进行中使用主色，普通信息使用二级文字。

### 5.4 检索结果与工具调用

**检索结果卡片。** 必须可回溯到具体文档与段落。卡片头部左侧显示来源（文件名、段落序号、字符区间），右侧显示置信度胶囊。卡片正文显示命中片段，底部为分数条。

**工具调用块。** 在会话中默认折叠为一行摘要，显示工具名、命中数与耗时。工具名固定为 `dsh_kb_search`，摘要行文案格式为「`dsh_kb_search · 5 条命中 · 38ms`」。展开后显示调用参数，包含查询语句 `query`、目标集合 `collection`（形如 `kb_prod_2f8a`）与 `topk`。工具名与参数使用等宽字体，耗时使用青绿语义色。

工具调用块是插件在会话中最主要的可见面，因此摘要行必须自解释：用户不展开也应能判断这次检索是否有效。

### 5.5 切分策略配置器

切分决定检索命中粒度：粒度太小丢失上下文，太大稀释相关性。

| 参数 | 规格 | 说明 |
|------|------|------|
| 切分方式 | 分段控件，按标题层级 / 按段落 / 固定长度 | 默认按标题层级 |
| 分片长度 | 数值输入，默认 1024 token | 与重叠长度联动校验 |
| 重叠长度 | 数值输入，默认 128 token | 必须小于分片长度 |
| 最小分片 | 数值输入，默认 64 token | 低于该值的分片直接丢弃 |
| 特殊处理 | 复选，保留代码块 / 表格按行拆分 | 独立开关，互不影响 |

配置器必须内嵌分片预览：展示前若干片的 token 数、来源与重叠量，并在底部给出汇总（总片数、平均 token、丢弃碎片数）。预览是提交前唯一的质量校验手段，不允许省略。

### 5.6 嵌入与索引策略配置器

| 参数 | 规格 | 关键约束 |
|------|------|----------|
| 嵌入模型 | 下拉选择 | 选中后维度与距离度量自动对齐 |
| 向量维度与数据类型 | 只读展示，如 1024 与 VECTOR_FP32 | 必须与嵌入模型输出一致 |
| 距离度量 | 下拉，默认 cosine | 必须与向量归一化方式一致。**引擎默认值并非 cosine（实测为 IP），故必须显式设置，不能依赖默认** |
| 索引类型 | 分段控件，HNSW / IVF / DiskANN | HNSW 面向高召回低延迟，IVF 面向超大规模，DiskANN 面向磁盘常驻 |
| M | 数值输入，默认 32 | 每层邻居数，仅 HNSW 生效 |
| efConstruction | 数值输入，默认 200 | 候选集大小，仅 HNSW 生效 |
| 量化器 | 下拉，默认 INT8 | 选项文案必须写明压缩比与召回损失。**引擎提供 FP16 / INT8 / INT4 三档，不存在 PQ 系列**（原文的 PQ-INT8 对应 INT8，即 FP32→INT8 的 4 倍压缩）。INT4 压缩更高但召回损失更大；关闭量化以存储换取召回 |
| 混合检索权重 | 数值，稠密向量与全文检索之和为 1 | 融合方式固定为 RRF |

维度与距离度量以只读参数网格呈现，不作为可编辑输入项。这两项配错会导致索引整体失效，不应交给用户在此处试错。

量化器选项必须标注压缩比与召回损失，二者是同一取舍的两端：压缩比越高，存储越小而召回越低。文案只写「INT8」而不说明代价，会让用户在不知情的前提下牺牲检索质量。

配置器底部必须给出代价预估（分片总数、向量存储、预计构建耗时），并在此之后才提供提交按钮。

| 区块 | 内容 |
|------|------|

重建索引期间，检索工具返回上一次快照，不中断正在进行的会话。该行为必须在界面上明确告知，避免用户误判为数据不一致。

### 6.4 检索测试与 RAG 问答

左右联动：左侧调试检索参数并查看原始命中，右侧把命中结果交给模型生成带引用的回答。两侧共用同一次查询，构成「调参至验证」的闭环。

左侧查询卡包含参数胶囊（topk 与阈值）、查询输入框与命中结果列表。命中结果卡片按分数降序排列，每张卡片包含来源、分数、片段与分数条。

右侧回答面板包含提问气泡、回答正文、引用来源列表与追问建议。

| 区域 | 关键约束 |
|------|----------|
| 引用来源 | 必须标注序号、文件名、定位与分数，序号与正文引用角标对应 |
| 兜底文案 | 命中分数低于阈值时返回「未在知识库中找到依据」，不允许模型自由发挥 |
| 免责说明 | 面板底部说明回答仅基于命中内容生成 |

### 6.5 索引策略配置

切分策略与嵌入策略的完整配置面。页面为双栏结构：左栏为切分策略与分片预览，右栏为嵌入与索引策略、混合检索权重与代价预估。

页头提供「重置为推荐值」与「保存并重建索引」两个操作。主按钮文案必须包含「重建索引」，因为参数变更不会自动生效。页头副文案需同步说明该约束。

## 7 深色主题规范

本章是深色主题的实现契约。深色主题不是浅色主题的机械反转，而是对明度关系的重新组织：本章给出令牌取值、五条实现规则、深色画板清单与三张深色界面的落地要点。

### 7.1 深色主题设计原则

以下五条是深色稿与浅色稿差异的全部来源，实现时逐条核对，不做主观发挥。

| 规则 | 要求 |
|------|------|
| 层级靠明度，不靠阴影 | 面板提升一档表面色即可区分层级；投影在深底几乎不可见，只保留给弹层与抽屉。 |
| 正文不用纯白 | 正文一律取 #EDF0F5，规避深底上的光晕效应；纯白只留给需要最高注意力的强调文字与图标。 |
| 描边成为必需品 | 深色下相邻表面的明度差很小，卡片、输入框、分隔线一律补 1 像素 #2C313C 描边。 |
| 大面积不用高饱和实色 | 品牌色只承担小面积（主按钮、图标、选中条）；大面积选中改为品牌底纹 #1E2140 配描边 #33396B。 |
| 图标与线条必须换色 | 浅色稿的 #5B6472 线条在深底不可读，统一替换为 #A7B0BF（常规）或 #EDF0F5（激活）。 |

### 7.2 深色画板清单

深色主题在设计稿中独立成稿，共 4 个画板，与浅色稿共用同一套语义令牌、栅格与信息密度。

| 序号 | 名称 | 内容 |
|------|------|------|
| 01 | 深色主题令牌 | 中性色阶 10 阶、品牌色阶 6 阶、语义状态 5 态、置信度 4 档，以及五条实现规则 |
| 02 | 知识库总览 · 深色 | 统计行、筛选工具条、知识库卡片网格与构建记录表 |
| 03 | 知识库详情与构建 · 深色 | 知识库头卡、选项卡、文档列表与构建配置双栏 |
| 04 | 检索测试与 RAG · 深色 | 查询卡、命中结果列表、带引用的回答面板与追问建议 |

深色主题不追求纯黑。画布底、应用底与卡片面之间保持约三档明度差，用户才能在不看边框的情况下感知层级。

### 7.4 深色语义状态与置信度

深色下的状态色一律采用「低饱和底纹 + 同色描边 + 高饱和圆点」三件套。只靠前景色识别状态，在深底上极易误读；文字色统一提亮一档，保证 WCAG AA 对比度。

| 状态 | 实色 | 底纹 | 描边 | 文字色 |
|------|------|------|------|--------|
| 就绪 | #2FB3A4 | #0F2E2B | #1D4A45 | #2FB3A4 |
| 构建中 | #E0A33A | #33270F | #57421B | #E0A33A |
| 失败 | #EE5A73 | #35141B | #5C2333 | #EE5A73 |
| 待构建 | #8A93A3 | #1E2128 | #2C313C | #A7B0BF |
| 信息 | #5A97EE | #122340 | #1E3C6B | #5A97EE |

检索置信度四档沿用同一分档边界，色值提亮以维持深底可读性：强相关 #2FB3A4、相关 #8BBA4E、一般 #E0A33A、低相关 #EE5A73。这四色是深色界面中唯一允许出现的高饱和区域，用于保证分数一眼可辨。

### 7.5 深色界面落地要点

| 区域 | 要点 |
|------|------|
| 应用外壳 | 侧栏与顶栏抬升一档表面色 #171A20，主区维持应用底 #121519；顶栏底部保留 1 像素 #2C313C 分隔。 |
| 导航选中态 | 由浅色稿的品牌浅底改为品牌底纹 #1E2140 配 1 像素描边 #33396B，图标与文字使用 #9AA2F0。 |
| 主按钮 | 填充提亮为 #6F7BE8，文字使用墨色 #0B0D10 而非白色，保证小字号下的对比度达标。 |
| 次级按钮 | 填充 #1D2128 配描边 #3A404D，文字 #EDF0F5。 |
| 内容卡片 | 统一填充 #171A20 配 1 像素 #2C313C 描边，不使用投影；卡片内嵌行使用 #1D2128。 |
| 分段控件与视图切换 | 槽色 #1D2128，选中项 #2C313C；不使用浅色稿的白色滑块配阴影方案。 |
| 进度条与分数条 | 槽色统一为 #2C313C，填充沿用受信语义色；禁止沿用浅色稿的 #EDEFF4 槽色。 |
| 构建日志 | 底色 #0B0D10 配等宽字体；成功行青绿、进行中主色、普通信息 #A7B0BF。 |
| 文件类型图标 | Markdown 使用 #A7B0BF、PDF 使用 #EE5A73、DOCX 使用 #5A97EE、TXT 使用 #8A93A3。 |

深色主题下禁止使用纯黑 #000000 作为任何表面色，也禁止使用纯白 #FFFFFF 作为正文色。两处越界都会在 OLED 屏幕与低亮度环境下产生明显不适。

### 7.6 主题切换与对比度底线

深色主题沿用浅色主题的可访问性底线：正文与背景对比度不低于 4.5 : 1，大字与图形不低于 3 : 1。深色下的风险点集中在语义文字与品牌文字，验收时必须单独抽样核对，不能直接沿用浅色稿的检测结果。

实现上通过变量模式切换：颜色令牌在同一个令牌集合内定义浅色与深色两组取值，页面不感知当前主题，只引用语义令牌。禁止在业务样式中为深色主题编写任何硬编码色值分支，也禁止用滤镜反色实现深色模式。

## 8 交互与状态规范

### 8.1 组件分层与状态覆盖要求

**组件按职责分为四层，各层要求不同。** 这一分层是必需的：v1.1.0 要求「每个组件实现五态」，但标记类组件（状态胶囊、计数徽标、标签）不是控件，为其编造 hover 与 loading 态会产生用户永不触达的状态，反而使状态语义失真。

| 分层 | 判定标准 | 状态要求 | 本规范涉及的组件 |
|------|----------|----------|------------------|
| **交互控件**（interactive） | 用户可操作并产生行为 | **五态齐备**：default / hover / focus / disabled / loading | 按钮、图标按钮、文本框、搜索框、文本域、下拉选择、开关、复选框、单选、分段控件、选项卡、上传区 |
| **标记**（marker） | 只表达状态或分类，自身不可操作 | **不得声明交互态**；必须满足状态三件套（文字 + 实色 + 描边） | 状态胶囊、标签、计数徽标、进度条 |
| **容器**（container） | 组织与承载内容，点击自身不产生行为 | 无状态要求；仍受配色与尺寸令牌约束 | 卡片、面板、页面、对话框框架、列表行、空状态面板 |
| **指示器**（indicator） | 本身即某种状态的呈现 | 无状态要求 | 加载指示器（Spinner） |

三条约束使该分层不成为漏洞：

1. **分层必须显式声明。** 每个组件样式表都要在构建门禁中登记所属层级与理由；未登记的样式表直接失败，新增组件必须做出判断。
2. **标记层禁止偷跑交互态。** 标记类组件若声明了 hover / focus / loading，视为违规——正确处理是改判为交互控件并补齐其余状态，而不是保留半成品可供性。
3. **容器层不受豁免。** 容器仍须通过配色字面量与裸尺寸检查；容器内真正的控件在自己的样式表内声明状态，状态检查正是到那里去看。**易碎点**：若容器内有可操作元素却未独立成组件（如可点击的卡片框架），该元素会绕过状态检查——因此容器内任何可操作元素都必须抽为交互控件。

`default` 态是组件的基准样式，不构成独立规则，故门禁不单列；其余四态（hover / focus / disabled / loading）可机械校验。

### 8.2 数据区域的五态覆盖

所有数据驱动的区域必须实现完整状态，缺一不可。

| 状态 | 要求 |
|------|------|
| 加载中 | 使用骨架屏而非空白页，骨架形状与最终内容一致 |
| 空状态 | 说明为什么为空、下一步能做什么，并提供主操作入口 |
| 错误态 | 说明失败原因、影响范围与恢复方式；不允许只显示错误码 |
| 成功态 | 关键写操作完成后给出明确确认反馈 |
| 受限态 | 权限或配额不足时说明限制来源与解除路径 |

**筛选后为空与真正的空是两种状态。** 列表被筛选或搜索后无结果时，必须说明「当前条件下无结果」并提供清除筛选的入口，不得复用「尚无数据」的空态——否则用户会把筛选结果误读为数据缺失。

### 8.3 反馈与确认

写操作必须有明确反馈。构建、上传等长任务需要可观察的进度与可取消入口。不可逆操作必须二次确认，并在确认文案中写明影响范围与是否可恢复。

**按页唯一主操作。** 同一页面同一时刻只允许一个 primary 按钮，承担该页的主操作。空态若需给出主操作入口，应指向页头已有的主按钮，而不是再渲染一个 primary——「全页唯一」是静态属性，不因空态与列表互斥而放宽。

**负向校验必须说明可接受范围。** 校验失败必须同时给出「哪里不对」与「什么是可接受的」，包括格式白名单或取值区间。仅提示「输入有误」或仅说明错误而不说可接受范围，均视为未完成。

### 8.4 键盘与可访问性

| 项 | 要求 |
|----|------|
| 焦点可见 | 所有可交互元素必须有可见焦点态，禁止移除轮廓；焦点用描边 + 外发光表达，不用投影 |
| 触达顺序 | 键序与视觉顺序一致，上传区、拖拽区必须可键盘触达 |
| 拖拽区可键盘触达 | 拖拽上传区必须渲染为可聚焦控件（button），拖拽只是增强路径而非唯一路径 |
| 图标语义 | 纯图标按钮必须提供可访问名称 |
| 状态语义 | 状态标记不得仅靠颜色区分，必须附文字 |
| 动效克制 | 尊重系统减少动效设置，禁用非必要位移与缩放 |
| 对比度 | 正文与背景对比度不低于 4.5 : 1，大字与图形不低于 3 : 1 |
| 长任务不遮挡 | 上传等长任务的进度必须在列表行内展示，禁止全局遮罩；并发任务各自独立进度 |

## 9 工程落地对照

### 9.1 zvec 概念与界面映射

界面术语必须与 zvec 的实际模型对齐，避免自造概念导致排查困难。

| zvec 概念 | 界面表达 | 说明 |
|-----------|----------|------|
| Collection | 知识库 | 提供集合标识用于日志对账，命名形如 `kb_prod_2f8a`（业务域缩写 + 短哈希） |
| Doc | 文档 | 保留原始文件名与类型 |
| vectors / embedding | 向量维度与数据类型 | 只读展示，与模型统一 |
| Index（HNSW / IVF / DiskANN） | 索引类型 | 分段控件选择 |
| Quantizer（INT8 / INT4 / FP16） | 量化器 | 选项文案标注压缩比与召回损失 |
| Full-text search（BM25 / n-gram） | 全文检索 | 参与混合检索权重 |
| Hybrid query | 混合检索权重 | 融合方式固定为 RRF |
| topk | 结果条数 | 查询参数胶囊 |
| 距离值 | 命中分数 | 归一化后展示，不暴露原始距离 |

### 9.2 DSH 插件契约与界面映射

| 插件能力 | 界面载体 | 关键约束 |
|----------|----------|----------|
| host 能力（工具注册） | 会话内工具调用折叠块 | 摘要行必须自解释 |
| 持久化 | 侧栏存储用量卡、构建配置区 | 路径需在工作区隔离 |
| 长任务 | 索引构建流水线 | 必须暴露进度、取消与失败重试 |
| 检索工具 `dsh_kb_search` | 检索测试页与工具调用块 | 前后端字段命名保持一致；入参固定为 `query`、`collection`、`topk`，出参含归一化后的 `match_score` |

### 9.3 令牌与样式变量对照

颜色与尺寸令牌需落为 CSS 自定义属性，双主题通过选择器覆盖。构建期消费建议使用 W3C Design Tokens JSON，避免手工维护多份色值。

**三产物同源。** 令牌源文件须同时产出 W3C Design Tokens JSON、CSS 自定义属性与 SCSS 变量，且三者由同一脚本生成并逐字节校验，不一致即失败。**SCSS 变量在构建期被替换，不随主题切换**，因此只导出浅色值，深色值以 `-dark` 后缀单独命名；凡需随主题变化的样式必须引用 `var(--kb-*)`，该约束须写在生成文件头部。

禁止事项：在业务样式中硬编码颜色与尺寸、使用令牌之外的中间色、通过提高选择器权重覆盖组件样式、在组件样式中为深色主题写条件分支（深浅差异一律由令牌取值承担）。

### 9.4 组件实现清单与优先级

| 优先级 | 组件 | 分层 | 依据 |
|--------|------|------|------|
| P0 | 按钮、表单控件、状态胶囊、知识库卡片、文档行、上传区 | 交互 / 标记 / 容器 | 构成所有页面的最小可用集合 |
| P1 | 索引构建流水线、检索结果卡片、工具调用块、分片预览 | 容器 / 标记 | 承载核心功能的可见性 |
| P2 | 切分与嵌入策略配置器、构建记录表、混合检索权重 | 交互 / 容器 | 面向进阶使用者的参数控制 |
| P3 | 空状态、骨架屏、追问建议、计数徽标 | 容器 / 标记 | 体验完善项 |

**组件总数与状态门禁。** 组件实现须在构建门禁中逐一声明所属分层（见 8.1）与不入交互态的理由；门禁校验交互控件的四态（hover / focus / disabled / loading）、标记类不得声明交互态、以及全部组件不得出现裸色值与裸尺寸。

## 10 待决事项与后续计划

### 10.1 待决事项

以下事项尚需业务侧确认后方可冻结，当前设计取通用默认值。

| 事项 | 当前取值 | 需确认内容 |
|------|----------|------------|
| 切分默认值 | 按标题层级，分片 1024，重叠 128 | 若主要面向代码库或短文本场景，应改为固定长度并下调分片长度 |
| 量化器默认 | INT8 | **规范原文记 PQ-INT8，但 zvec 0.7.1 的 `ZVecQuantizeType` 只有 FP16 / INT8 / INT4，不存在 PQ。** 对应关系为 FP32→INT8 的 4 倍压缩。若对召回率要求优先于存储，应关闭量化（`UNDEFINED`）。RaBitQ 属索引类型族（`HNSW_RABITQ` / `IVF_RABITQ`）而非量化器，且为 Linux 专用，是否对用户暴露待确认 |
| 索引类型默认 | HNSW | 若规模达到百万分片以上，应改为 IVF 或 DiskANN。引擎实际含 `HNSW` / `IVF` / `FLAT` / `HNSW_RABITQ` / `DISKANN` / `IVF_RABITQ` / `INVERT` / `FTS` |
| 距离度量 | COSINE（须显式设置） | **引擎的 `metricType` 默认值为 IP（内积），不是 cosine。** 必须按索引显式设置，否则分数尺度与 0.55 阈值全部失准 |
| 相似度阈值 | 0.55 | 需按实际语料分布回归后确定 |
| 深色主题界面 | 令牌与三张核心界面稿已交付 | 待补空状态、加载与错误态的深色稿 |
| 云同步与共享 | 本期未纳入 | 当前为纯本地（`zvec · local`），是否需要多端同步与团队共享待确认 |

### 10.2 实施期回补的引擎实测偏差

以下三项在实施阶段经真机验证（`@zvec/zvec` 0.7.1，win32-x64），与本文档的技术假设不符，已按实测实现并在此回写，避免后续实现照着不存在的假设去写。

| # | 原文假设 | 实测结论 | 处置 |
|---|----------|----------|------|
| 1 | 命中分数由距离归一化得到（3.4 表述方向正确） | `querySync` 返回的 `score` 是**距离**（越小越相似，列表已按距离升序）；查询向量等于某文档得 0，正交得 1 | 归一化必须实现为 `matchScore = clamp(1 - distance)`，而非对原值 clamp。方向读反会把最差命中排在最前，并让全部命中越过 0.55 阈值 |
| 2 | 量化器为 PQ-INT8（压缩 4×） | 量化器只有 `FP16` / `INT8` / `INT4`，**不存在 PQ** | 配置器选项与默认值改为 `INT8`；「压缩 4×」对应 FP32→INT8 |
| 3 | 索引类型 HNSW / IVF / DiskANN | 实际含 `HNSW` / `IVF` / `FLAT` / `HNSW_RABITQ` / `DISKANN` / `IVF_RABITQ` / `INVERT` / `FTS` | 分段控件至少覆盖 HNSW / IVF / DiskANN；两个 RaBitQ 变体待业务确认是否暴露 |
| 4 | 距离度量默认 cosine（5.6） | HNSW / IVF / DiskANN / FLAT 的 `metricType` **默认值均为 IP** | 必须按索引显式设置 `COSINE` |
| 5 | 集合可反复按建库方式打开 | `ZVecCreateAndOpen(path, schema)` 要求 `path` **不存在**；重开既有集合必须走 `ZVecOpen(path)`，且不接收 schema | 集合打开分两条路径（新建 / 重开），按存在性分派；schema 随集合持久化 |
| 6 | —— | 集合目录为**独占锁**：同一路径第二次打开必然失败（含只读）；「路径已存在」报的是 `ZVecInvalidArgument` 而非「已存在」 | 句柄须按槽位池化并引用计数，不能按请求开闭；卸载时须释放，否则重载撞锁 |
| 7 | 重建索引期间旧索引仍可读 | 引擎不支持同目录双开，故「旧快照继续服务」须由**双槽位 + 指针切换**实现 | 写入非活动槽，发布时原子翻转指针 |
| 8 | —— | 标量过滤语言只接受**单等号 `=`**，`==` 为语法错误；字符串用单引号 | 过滤表达式统一由 `documentFilter()` 生成并转义 |
