# KB-REF-01 — 抽取并测试 collection 解析纯函数

**What to build（要构建什么）：** 一个把「用户说了哪个知识库」翻译成「collection 标识」的纯解析逻辑，独立于向量库与嵌入模型即可穷举验证。它是后续一切行为的地基：先立门禁并确认其为红，再改行为。

**Blocked by:** 无 —— 可立即开始。

**Status:** ready-for-agent

## 背景（为什么存在这条 issue）

`@` 引用知识库的菜单**已实现并已注册**（客户端触发源在会话输入区注册成功）。选中后 chip 在提交时会序列化成一句话交给模型，其中**已经含有正确的 collection 标识**，例如：

```
（用户指定本次回答使用知识库「agent-book」：调用 dsh_kb_search 时 collection 参数传 "kb_agentbook_5eed"）
```

但实际发生的调用把**显示名**当成了标识（`collection="agent-book"`），检索以「集合标识非法」失败，再靠一次额外往返去拿清单。

也就是说：链路每一段都对，唯独**「文本里提到了标识」→「参数真的使用了这个标识」**这一跳没有任何代码保证。本组 issue 的目标，是让参数解析由代码保证，而不是依赖模型照抄散文。

## 范围

实现一个**纯函数**：给定调用方传入的 collection 字符串与当前可见知识库清单，返回一个明确的解析结果。

- 输入归一化：去首尾空白；名称匹配忽略大小写。
- 从**整句序列化模板**中抽取标识：模板是"散文 + 引号内的标识"，需要识别并取出引号内的值；抽不到就把整串当名称再试。
- 四种结果：**命中唯一标识** / **歧义（多个候选）** / **无匹配** / **输入为空**。
- 不抛异常，返回可判定的结果（与既有检索工具「失败语义不抛异常」的约定一致）。
- 解析顺序：精确标识 → 精确名称（忽略大小写）→ 唯一名称前缀 → 歧义 → 无匹配。

**不得**在解析中触碰文件系统、存储句柄或嵌入模型 —— 这正是它可被穷举测试的原因。

## 验收标准

- [ ] 存在一个可独立导入的纯解析函数，签名接受「输入字符串」与「知识库清单（含标识与名称）」两个参数。
- [ ] 裸标识（形如 `kb_agentbook_5eed`）精确命中，结果与直接使用该标识一致。
- [ ] 显示名（`agent-book`）解析到对应标识。
- [ ] 显示名大小写变体（`AGENT-BOOK`）解析到同一标识。
- [ ] 唯一前缀（`agent`，仅匹配一个知识库时）解析到该标识。
- [ ] 整句序列化模板（形如上述带引号的句子）能被抽取并解析到引号内的标识。
- [ ] 两个知识库命中同一输入时，返回**歧义**并携带全部候选，**不静默取第一个**。
- [ ] 无任何候选时返回**无匹配**，并携带当前全部可用知识库。
- [ ] 空字符串或纯空白输入返回**输入为空**。
- [ ] 存在自动化校验脚本，覆盖上述全部用例，且可随 `npm run verify` 运行。

## 证据要求

新增的校验脚本必须**先确认其为红**（在解析函数尚不存在或行为不符时失败），再实现到全绿 —— 否则修完无从证明。

## 不做

- 不改动检索工具的对外契约（`query` / `collection` / `topk` 字段名与取值形状）。
- 不接入真实存储、不调用嵌入模型、不发起网络请求。
- 不修改客户端触发源的行为。
