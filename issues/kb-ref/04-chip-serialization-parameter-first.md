# KB-REF-04 — chip 序列化改为参数片段优先

**What to build（要构建什么）：** 从 `@` 菜单选中的知识库，提交后交给模型的文本以「参数名 = 值」的形状开头，而不是一句自然语言描述，从而降低被当成背景说明忽略的概率。

**Blocked by:** KB-REF-02（代码级保证必须先就位）。

**Status:** ready-for-agent

## 背景

当前 chip 序列化成一句完整的说明文字：

```
（用户指定本次回答使用知识库「agent-book」：调用 dsh_kb_search 时 collection 参数传 "kb_agentbook_5eed"）
```

标识确实在其中，但它以**散文**形式出现，模型把它读作背景说明而非参数约束，仍然凭上下文中的名称去填参数。改为以参数片段开头：

```
collection="kb_agentbook_5eed"（知识库「agent-book」，用户已通过 @ 指定）
```

## 关于本 issue 的证据强度（必须阅读）

这是一条**启发式改进**。它**无法**用自动化测试证明"模型一定会照做" —— 那取决于模型行为，不在本仓库的可验证范围内。

因此：

- 它**必须依赖 `KB-REF-02`**。`KB-REF-02` 提供的是**代码级**保证（无论模型怎么写，参数都能解析正确）；本 issue 只降低模型误读的概率。
- **单独上线本 issue 是无意义的** —— 那等于"只改提示措辞、不改代码"，而这恰恰是当前缺陷的成因。
- 本 issue 的完成**不得**被当作 `KB-REF-02` 的替代或充分条件。

## 范围

- 修改 chip 的**模型序列化**文本：以参数片段开头，标识紧随其后，名称作为补充说明置于括号内。
- 序列化仍为异步、仍观察中止信号；序列化失败仍**阻断发送**，不得静默降级。
- **剪贴板形态保持不变**（仍为 `@名称`）—— 那是给人看与粘贴的，与交给模型的文本职责不同。
- 名称查不到时降级为标识本身，不阻塞发送（既有行为保留）。

## 验收标准

- [ ] 选中知识库后，交给模型的文本以 `collection="<标识>"` 形状开头。
- [ ] 文本中仍包含人类可读的知识库名称，便于追溯。
- [ ] 剪贴板/剪切后的形态仍为 `@名称`，未变为标识或参数片段。
- [ ] 中止信号已触发时序列化拒绝，且发送被阻断。
- [ ] 名称查询失败时仍能产出以标识开头的文本，发送不被阻塞。
- [ ] 既有全量校验套件保持全绿。
- [ ] 校验脚本覆盖序列化的新形状与上述降级分支。

## 证据要求

给出**修改前后**的序列化文本对照。同时明确记录：本 issue 不声称已解决参数误用问题 —— 该保证由 `KB-REF-02` 提供。

## 不做

- 不改动剪贴板文本形态。
- 不改动客户端的候选列表、菜单分组或注册链路。
- 不以此 issue 替代或弱化 `KB-REF-02`。
