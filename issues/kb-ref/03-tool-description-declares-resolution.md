# KB-REF-03 — 工具描述声明 collection 的解析语义

**What to build（要构建什么）：** 模型知道 `collection` 可以传知识库名称、也知道通道有多真实 —— 从而不再把显示名当非法输入，也不再需要靠一次失败去发现约定。

**Blocked by:** KB-REF-02（解析行为必须先真实存在）。

**Status:** ready-for-agent

## 背景

工具描述是模型了解调用约定的**唯一场所**。当前描述把 `collection` 描述为"集合标识，形如 `kb_prod_2f8a`"，这正是模型把显示名当非法值、进而先失败一次的成因之一。`KB-REF-02` 已让名称可用，但**未告知模型**，通道就仍是隐性的。

**顺序不可颠倒**：描述是对行为的承诺。若行为尚未支持名称就先行声明，描述即成为谎言。

## 范围

- 工具的 `description` 中，说明 `collection` 可传**集合标识或知识库名称**，由宿主解析。
- 说明重名时的后果：**报错并列出候选**，要求调用方从候选中选择，而非改写为猜测值。
- 说明用户以 `@` 引用知识库时：**直接使用引用中给出的 collection 取值，不要改写、不要翻译**。
- 参数说明同步更新，与新语义一致。
- 措辞须与 `KB-REF-02` 的**实际**失败原因与说明文本一致（含新增的歧义一档）。

## 验收标准

- [ ] 工具描述明确写出 `collection` 接受**标识或名称**两种形态。
- [ ] 工具描述写出重名时返回歧义并列出候选，且要求从候选中选择。
- [ ] 工具描述写出 `@` 引用场景下应直接使用引用中的取值。
- [ ] 参数说明与工具描述**不矛盾**（不得一处说可传名称、另一处仍要求形如 `kb_prod_2f8a`）。
- [ ] 描述中提到的失败原因与工具**实际**返回的失败原因集合一致。
- [ ] 参数名 `query` / `collection` / `topk` 未被改动。
- [ ] 既有全量校验套件保持全绿。

## 证据要求

以工具注册后的实际描述文本为证据，逐条对照上述声明，确认与实际行为一致。

## 不做

- 不新增或重命名工具参数。
- 不改变返回结构中既有字段的名称与含义。
- 不在描述中写入仅供内部使用的实现细节（例如解析的匹配顺序）。
