## 1 拆分原则

1. **同源码位置的缺陷合并**：B1 与 B6 都在 `retrieval.ts` 的同一个循环里，分开修会互相破坏，必须合并为一条。
2. **共享重建窗口的合并**：B2（改 FTS schema）与 B9（改分片内容）都要求已有集合全量重建。**合并执行可省一次重建成本**。
3. **先立门禁，再改行为**：B5 的断言必须在修复前写好并确认为红，否则修完无从证明。
4. **不改 spec 已冻结的对外契约**：`query` / `collection` / `topk` / `match_score` 的字段名与分档边界（§3.4）不得变动。
5. **每条 issue 必须可独立验收**：改完能跑出证据，且不依赖后续 issue。

## 3 Issue 详情

### KB-FIX-01 · 分数语义与 topk/floor 归因

| 项 | 内容 |
|----|------|
| 缺陷 | B1（`retrieval.ts:133`）、B6（`retrieval.ts:139`） |
| 依据 | spec 行 626、606（§9 §1）；行 467 |
| 服务端文件 | `plugin/src/store/retrieval.ts` |

**范围**

- 删除把 **RRF 融合分**当距离的回退分支（`denseScore.get(doc.id) ?? toMatchScore(doc.score)`）。RRF 分只能用于**排序**，不得进入 `match_score`。
- 全文独有命中（无稠密距离）需有**显式的低证据语义**，不得伪装成高相似度。
- 修复循环的 topk 与阈值归因：**先按分数过滤，再取前 topk**；`belowFloor` 只统计真正低于阈值的条数，不得把「被 topk 上限挤掉」计入。
- `mode` 的语义保持 `'hybrid' | 'dense'` 不变。

**验收标准**

- [ ] 不再存在任何把 RRF 分传入 `toMatchScore` 的代码路径。
- [ ] 对同一查询，分数**不再全部落在 < 0.05 宽的带内**。
- [ ] `topk=3` 且存在 ≥3 条合格命中时，返回 3 条（不再 under-fill）。
- [ ] 被 topk 上限排除的命中**不**计入 `below_count`。
- [ ] `below_floor` 的语义与工具描述一致（"低于阈值被过滤的条数"）。

**不做**：改变 §3.4 的分档边界；改变对外的 `match_score` 字段名。

### KB-FIX-02 · 召回顺序改为稠密优先

| 项 | 内容 |
|----|------|
| 缺陷 | B7（`retrieval.ts:110`）、S3（权重控件无效）、`BuildPage.tsx:222` |
| 依据 | spec 行 408「HNSW 召回 → PQ-INT8 解压重排 → RRF 混合融合」；行 374 权重 |
| 服务端文件 | `plugin/src/store/retrieval.ts`；客户端 `BuildPage.tsx` / `panel.tsx` |

**范围**

- 使召回以**稠密向量为主通道**，全文为补充，符合 spec 行 408 的顺序。
- **裁决权重控件的去留（二选一，不得保留"可调但无效"）**：
  - (a) 若引擎支持加权融合 → 把 `HYBRID_DEFAULTS` / `validateWeights` 真正接进检索；
  - (b) 若引擎的 RRF 不收权重 → **移除**客户端权重控件，并在 spec §5.6 回写"RRF 融合不适用权重"。
- 先做**引擎能力探测**（`multiQuerySync` 是否收权重参数），再决定 (a)/(b)。

**验收标准**

- [ ] `topk=1` 时返回的是**稠密最佳**命中，而非 RRF 榜首。
- [ ] 若保留权重控件：断言权重**确实影响**返回顺序（负向测试：改权重结果必须变）。
- [ ] 若移除权重控件：断言界面上不再出现该控件，且 spec §5.6 已回写。
- [ ] 权重相关代码**不得**留下无读者的导出。

### KB-FIX-03 · FTS 中文分词 + 强制全量重建判定

| 项 | 内容 |
|----|------|
| 缺陷 | B2（`collection.ts:109`） |
| 依据 | spec 行 626 / §9 §9（引擎支持 `standard`/`ngram`/`jieba`/`whitespace`） |
| 服务端文件 | `plugin/src/store/collection.ts`、`snapshot.ts`、`operations.ts` |

**范围**

- FTS 字段建索引时指定 `tokenizerName: 'jieba'`。**实测依据**：`jieba` 把 `翁家翌` 从 9 条收敛到**恰好 1 条**，`狼人杀` 从 22 条收敛到 0 条；`ngram` 会让 `qwertyuiop` 匹配 69 条，不可用。
- **把分词器纳入 schema 指纹**：`SnapshotMeta` 记录所用分词器；`incrementalViability` 在分词器变更时**强制全量重建**（与索引参数变更同级）。
- 增量构建走 `cloneSlot()` 克隆旧 schema，**必须**确保它不会沿用旧分词器。

**验收标准**

- [ ] 新建集合的 FTS schema 带 `tokenizerName='jieba'`。
- [ ] 分词器变更时 `incrementalViability` 返回 `possible: false` 且原因具名。
- [ ] 语料中不存在的多字中文串返回 **0** 命中（现状返回 200 条）。
- [ ] `翁家翌` 查询的命中数 ≤ 3（现状 66）。
- [ ] 全量重建后检索在**完整实体 chunk** 上命中。

**不做**：引入外部分词依赖；改变 `standard` 分词器对纯 ASCII 的行为。

### KB-FIX-04 · 重叠长度真正生效

| 项 | 内容 |
|----|------|
| 缺陷 | B9（`chunk.ts:555`） |
| 依据 | spec 行 372、373、382、459 |
| 服务端文件 | `plugin/src/store/chunk.ts`；`strategy.ts`（成本估算） |

**范围**

- **在窗口化阶段真正制造重叠**：`sizeWindows()` 接收 overlap，每片起点从上一片末尾回退（token → 字符折算），且**必须保证前进**（防死循环）。
- `splitSegment()` / `chunkDocument()` 把 `config.overlapTokens` **透传**下去（当前无传递路径）。
- `applyOverlap` 改为**校验**而非唯一实现（重叠产生后 `shared > 0`，此时其度量才正确）。
- 边界回退尊重语义边界（优先段落/句号），与现有 `lastIndexOf` 逻辑一致。
- **核对 `estimateCost` 的向量存储估算**：重叠会增大实际占用，估算需同步。

**验收标准**

- [ ] `overlapTokens=128` 时，相邻片**共享字符数 > 0**（现状恒为 0）。
- [ ] 预览的「重叠量」列**不再恒为 0**。
- [ ] 跨边界句子在相邻两片中**至少一片里完整**（现状 88/88 不可恢复）。
- [ ] `overlapTokens=0` 时行为与今天**完全一致**（不得回归）。
- [ ] 不产生死循环，分片数有限。
- [ ] `estimateCost` 的体积估算反映重叠后的真实占用。

**风险**：重叠回退点若落进代码块/表格内部，可能破坏 `preserveCodeBlocks` / `splitTablesByRow` 的保证 —— 需覆盖测试。

### KB-FIX-05 · 补区分度 / 负向 / 分词器 / 重叠门禁

| 项 | 内容 |
|----|------|
| 缺陷 | B5（`verify-*.mjs` 元缺陷） |
| 依据 | 本仓库既有惯例：加严判定须以**负向测试**验证会真实失败 |
| 文件 | `plugin/scripts/verify-*.mjs` |

**范围**

- 现有对真实引擎的分数断言**只有** `matchScore >= 0 && matchScore <= 1`（3 处），`0.984` 轻松通过。需补**语义**断言。
- 新增门禁（**必须在修复前确认为红**）：
  1. **区分度**：同一查询的分数不得全部落在 < 0.05 宽的带内；
  2. **排序**：已知含实体的 chunk 排第一，且显著高于次名；
  3. **负向**：语料中不存在的多字中文串 → 0 命中；
  4. **分词器**：新建集合 FTS schema 必须带 `tokenizerName`；
  5. **重叠**：`overlapTokens>0` 时相邻片共享字符 > 0；
  6. **槽回收**：发布成功后旧槽被清理（KB-FIX-08 完成后转绿）。

**验收标准**

- [ ] 每条新断言都先说清"现状为什么是红的"，并留档证据。
- [ ] 修复完成后，全部新断言转绿。
- [ ] 新门禁纳入 `npm run verify`。

## 4 风险与回滚

| 风险 | 缓解 |
|------|------|
| 改 `retrieval.ts` 影响 KB-08 的 75 项断言 | 先跑基线留档；对外契约（字段名/分档）不动 |
