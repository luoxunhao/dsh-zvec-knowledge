- 复制非可复用 frame 时，子节点会重新分配 ID，原 ID 路径（`副本ID+";"+原ID`）不可用；
  需先 `batch_read` 读回新 ID 再更新。BFS 分配：root → 各直接子节点 → 各孙节点。

- 横排容器内子元素用 `fill_container` 时，若子元素内含 `hug_contents` 文本，宽度会被文本撑开而不等分；
  把内部文本改成 `fill_container` 才能等宽。

## 环境经验（重要，可复用）

### tencent-docx 转换引擎环境
- 官方 `scripts/wb/local/setup-html-to-docx.sh` 在本机**不可用**：它依赖的 bash 工具链
  `dirname` 缺失（脚本 line 35 报 `dirname: command not found` + `cd: null directory`）；
  PortableGit 的 `usr/bin` 不在 PATH，手动补 PATH 也无效。
- `~/.venv-html-to-docx` 未被 SessionStart hook 创建，`uv` 也未安装。
- **可用替代路径**：用托管 Python 自建隔离 venv 并装依赖，仍走官方 html-to-docx 引擎：
  1) `C:\Users\admin\.workbuddy\binaries\python\versions\3.13.12\python.exe -m venv C:\Users\admin\.workbuddy\binaries\python\envs\html-to-docx`
  2) `envs\html-to-docx\Scripts\python.exe -m pip install --only-binary=:all: -r <plugin_root>\skills\html-to-docx\scripts\requirements.txt`
  3) `Set-Location <plugin_root>\skills\html-to-docx\scripts` 后 `python -m html_to_docx convert <in.html> -o <out.docx> --page-size A4 ...`
- 依赖清单（requirements.txt）：python-docx, html-for-docx, beautifulsoup4, lxml, httpx, Pillow, click, pytest。
- 托管 python 3.13.12 与 `C:\ProgramData\dlops-backend\python.exe` 自带 docx+lxml，但缺 click/bs4/Pillow。

### Windows 中文路径/参数的编码坑（本机反复踩到）
- **PowerShell 的 stdout 在本环境不被回显**：需把结果 `Out-File` 到文件再用 Read 读，不要依赖直接输出。
- **命令字符串里的中文字面量会被有损传递**：传给 python 的 argv 中文会变成 mojibake
  （`resolve_output_docx_path.py --filename "中文.docx"` 即为此例）。
  规避：把中文名写进 UTF-8 文件（用 Write 工具），再由 PowerShell 用 `Get-Content -Encoding UTF8` 读出使用。
- **路径含中文时不要手写字面量**：用 `(Get-ChildItem "<父目录>\*.html").FullName` 通配符取全路径，绕开编码。
- **Python 输出重定向会二次编码**（`*>&1 | Out-File -Encoding utf8` 会把 UTF-8 字节按 GBK 解码成 mojibake，
  只是显示层问题）。要拿到可信文本，让脚本**直接写 UTF-8 文件**（`json.dump(..., ensure_ascii=False)`）再用 Read 读取。
- **校验 docx 文本完整性**：用 python-docx 读 paragraph+table 文本拼接后再做 `in` 判断；
  不要直接对 `word/document.xml` 做字符串匹配（文本会被拆进多个 `<w:t>`，且转换器会在拉丁/中文字间插双空格）。

### zvec 实测偏差（重要，已回补进 issue 清单第 9 节）
1. **`querySync` 的 `score` 是距离不是相似度**：同一向量得 0，正交得 1，列表按距离升序。
   规范化必须 `matchScore = clamp(1 - distance)`。读反会把最差命中排最前并让全部命中越过 0.55 阈值。
2. **没有 PQ-INT8**：`ZVecQuantizeType` = FP16 / INT8 / INT4；RaBitQ 是索引类型
   （`HNSW_RABITQ` / `IVF_RABITQ`），不是量化器。规范的「PQ-INT8 压缩 4×」= INT8。
3. **默认度量是 IP（内积）不是 cosine**：HNSW/IVF/DiskANN/FLAT 的 `metricType` 默认全是 IP，
   必须显式设置 COSINE。
4. `ZVecCreateAndOpen(path, schema)` 要求 path **不存在**；重开既有集合走 `ZVecOpen(path)`，不收 schema。
5. 索引类型实际枚举还有 FLAT / INVERT / FTS，不止 HNSW / IVF / DiskANN。
- 验证数据：1.0 / 0.994 / 0.707 / 0（余弦理论值吻合），关掉重开数据一致，win32-x64 绑定可用。

### 本轮新踩的坑（重要）
1. **pnpm 在这台 Windows 上装不了依赖**：11.22.0 在 hoist 阶段以
   `UNKNOWN: unknown error, symlink '..\..\@types+prop-types@...'` 中止（exit -4094），只落
   `node_modules/.pnpm` 不建顶层链接；它算出的相对链接目标不指向虚拟仓。**`.npmrc` 里的
   `node-linker=hoisted` / `hoist=false` 均无效**——`pnpm config list` 里根本查不到这两个键，
   说明项目级 `.npmrc` 未被读取。**结论：这个包用 `npm install`**（不用符号链接，绕开整类问题）。
   注意 `dsh plugin --profile add` 走的是 pnpm，但 dsh 会给 profile 写 `nodeLinker: hoisted`，
   所以 profile 安装不受此影响。

### 两个新增的机械门禁（`scripts/verify-components.mjs`，已挂进 `npm run verify`）
1. **每个样式表必须被归类**为 `interactive` / `marker` / `indicator`，未归类即失败——强迫每个新组件先决定自己是不是控件。
   - interactive：必须有 hover / focus-visible / disabled / loading 四条规则（缺一即失败）
   - marker：**禁止**声明 hover / focus-visible / loading——胶囊长出 hover 就说明它在假装是控件，
     正确反应是归类成控件并补全五态
   - indicator：无要求
2. **无裸值**：`src/client/**/*.css`（除生成的 tokens 文件）不得出现十六进制 / rgb / hsl 字面量；
   每个 `px` 字面量要么是 `1px` / `-1px`（发丝线与 sr-only 偏移），要么在 `ALLOWED_PX` 里登记理由。
   扫描前先剥掉块注释——否则「外发光 4px 15%」这类**解释文字**会被当成值。

### 实现中发现并解决的坑
